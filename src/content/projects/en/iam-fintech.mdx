## Context

Global Estratégias Financeiras is a regulated Brazilian fintech that handles sensitive financial data. In that kind of environment, **permission drift is not a hygiene issue, it is a compliance risk**. The previous process relied on manual quarterly access reviews and ad hoc offboarding tickets, and every audit turned into a manual sweep because nothing could be answered from existing data.

- **Slow offboarding** — the window between "person leaves" and "access revoked" was measured in days, sometimes weeks. For a fintech, that window is the audit finding.
- **Access piling up across role changes** — users moved between teams and kept their old permissions, because nobody owned pruning them.
- **No history** — quarterly reviews showed the current state, never how it had changed since the last review.
- **Endpoint telemetry isolated from IAM** — a privileged user signing in from an unusual host was not visible next to that user's access-change history.

## What I did

I owned the IAM lifecycle and rebuilt it around three principles: state always known, transitions always logged, drift always detectable.

### Lifecycle automation

- **Hire → role change → offboard → audit.** Identity events from HR drove Active Directory group membership through PowerShell workflows, using the Microsoft Graph API for Microsoft 365, instead of tickets. On every role change, group membership was recomputed against a canonical role-permission matrix instead of accumulating by hand.
- **Automated offboarding.** When HR recorded a separation, the workflow disabled the AD account, removed its group memberships, archived the mailbox and logged every step to the audit trail, all within 10 to 15 minutes. Revocation no longer waited for someone to open a ticket.

### Hardening

- **3 critical Linux servers** — the financial-data layer — on a CIS-aligned baseline. Hardening was idempotent and scheduled, not one-shot, and drift between sweeps was the metric.
- **GPO baseline** applied across the Windows fleet.

### Endpoint and identity correlation

Bitdefender EDR and Windows Event Logs fed Wazuh alongside the IAM events. A privileged login from an unusual endpoint, a local administrator group change on a critical server and a service account moving laterally were correlated into one incident timeline, instead of three unrelated alerts on three dashboards.

### Designed for audit

A regulated fintech has to answer "who accessed what, from where, and when?" — for its LGPD obligations and for ISO 27001 access-control audits. The design choices map to that question:

- **The audit trail is the system** — every IAM transition, privileged login and group change is logged with timestamp, actor and context. The audit is a query against the same telemetry the SIEM uses, not a separate report.
- **Least privilege by default** — groups defined by role and recomputed on every role change. A user gains access only when the canonical role grants it.
- **A hardened baseline, not snowflake servers** — asked "what is hardened?", the answer is a number and a drift report.

## How it works

```mermaid
flowchart TB
    A[HR system] -->|Hire / role change / separation| B[IAM lifecycle workflows]
    B --> C[Active Directory]
    C --> D[Role-based group membership]
    D --> E[Application access]

    F[GPO baseline] -->|CIS-aligned| G[Windows fleet]
    H[CIS hardening] -->|3 critical servers| I[Linux servers]

    G --> J[Bitdefender EDR]
    I --> J
    G --> K[Windows Event Logs]

    J --> L[Wazuh SIEM]
    K --> L
    B --> L

    L --> M{Correlation}
    M -->|IAM event + endpoint anomaly| N[Incident alert]
    M -->|Routine activity| O[Audit trail]
```

HR events drive Active Directory through the lifecycle workflows. The same events, the EDR and the Windows logs all land in Wazuh, which raises an incident when an identity change and an endpoint anomaly line up and files everything else as audit trail.

## Business value

## Lessons

- **In a regulated environment, audit is the system.** The audit answer and the SIEM query became the same query, which is what ended the manual sweeps.
- **Offboarding is the metric that catches everything else.** Moving revocation from a ticket to the HR signal was the change that made least privilege believable.
- **Permission drift is the slow-motion incident.** Recomputing membership on every role change stopped access from piling up silently.
- **Endpoint telemetry without IAM context is half a story.** A privileged login from an unusual host only meant something next to the access change that preceded it.
